# Локальная сессия Instagram

Бот не принимает пароль Instagram и не использует сторонние downloader API.
Вход выполняет владелец отдельного аккаунта в отдельном профиле Firefox/Zen.
Не используйте основной профиль с несколькими аккаунтами/контейнерами Instagram.

1. Откройте `about:profiles` в Firefox/Zen, создайте отдельный профиль и запустите его.
2. Войдите своим отдельным аккаунтом на instagram.com обычным способом.
3. Сообщите имя этого профиля агенту. Если база браузера заблокирована, закройте
   окно этого профиля перед экспортом; обычная сессия остаётся сохранённой.
4. Экспорт выполняется локально, без расширений и внешних запросов:

```powershell
uv run python scripts/instagram_session.py --firefox-profile "ПОЛНЫЙ ПУТЬ К ПРОФИЛЮ"
```

Скрипт читает SQLite только в режиме read-only и выбирает только домены
instagram.com и его поддомены. Cookies других сайтов и пароль не экспортируются.
Требуется непустой действующий sessionid. Файл сохраняется в игнорируемый Git
`secrets/instagram.cookies.txt`; его содержимое не выводится в чат/логи.

Агент переносит этот файл по SSH в `/opt/threaddock/shared/instagram.cookies.txt`
с доступом для UID контейнера 10001 и правами 0600. Следующий штатный deploy
автоматически подключает его read-only через compose.cookies.yaml. Cookie jar
не попадает в Git, образ и резервную копию базы. Предварительный check и rollback
используют тот же read-only mount. После подключения проверяется именно исходная
неудачная ссылка, без публикации содержимого сессии.

Сессию может потребоваться обновить после выхода из аккаунта или отказа Instagram.
Подключение сессии не подменяет живую проверку доступа с IP сервера.
