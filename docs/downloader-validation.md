# Проверка загрузчика — 2026-11-17

Обновление надёжности развёрнуто из PR #17; последующее уточнение пользователя:
слайдшоу должно показывать фото по 3 секунды, независимо от длины музыки.
Полная приёмка Downloader 1.0
не объявляется пройденной до проверки всех обязательных сетевых сценариев.

## Автоматические проверки

Полный локальный прогон: Python unit/integration tests, Ruff, FFmpeg/ffprobe,
yt-dlp CLI, Deno и Chromium. Включает существующие проверки изоляции владельцев
архива, очереди, неопределённой доставки, восстановления, кнопок и очистки.
Дополнительно проверяются тихий fallback на фото при сбое музыки/рендеринга,
смешанные альбомы, групповые режимы и кнопки, предел 72 часа без продления,
видеодорожка Live Photo при её наличии в метаданных, одно фото с длинным/коротким аудио.

## Реальные источники

Локальная сеть, текущий lock-файл, без cookies источников:

| Сценарий | Наблюдение |
| --- | --- |
| Присланная пользователем TikTok Story, короткий URL | MP4 15,02 с, H.264/AAC, 576×1024. Проверены 15 кадров в разные секунды: 15 разных хешей, движение сохранено. |
| Присланный TikTok Photo Mode с Live Photo | Получены две JPEG и музыка, подготовлен MP4 15,65 с. В публичном состоянии страницы доступны только статичные изображения; видеочасть Live Photo отсутствует. Сохранение её движения **не подтверждено**. |
| Повторный запрос Story до добавления прямого page fallback | Наблюдался временный `source_blocked`. Успешная проверка не означает постоянную доступность источника. |

На VPS в изолированном контейнере с новым кодом, без production-данных:

- Photo Mode из присланной ссылки и YouTube: скачаны MP4 со звуком.
- Story из присланной ссылки: первоначально `source_blocked`, повторная попытка
  успешна со звуком. Отказы временные, число повторов ограничено.
- Instagram Reel и Story из upstream-примеров: `source_temporary`; успешная
  загрузка и отправка не подтверждены. Story из примера может быть устаревшей.
- Vimeo из upstream-примера: `authentication`, доступный файл не получен.

macOS ARM runner не получал задания: GitHub сообщил о нехватке capacity и
`The job was not acquired by Runner of type hosted even after multiple attempts`.
Матрица сохраняет проверку macOS на поддерживаемом `macos-26-intel`.

Диагностика Live Photo проверяла `/photo/`, `/video/`, публичный item detail,
embed/player и доступные публичные app endpoints. JPEG не содержат встроенного MP4.
Не используются сторонние сайты-загрузчики, чужие credentials или обход приватности.
Если TikTok отдаёт отдельный motion URL, он обрабатывается как видео в правильной
позиции смешанной публикации. Это не заменяет сетевую проверку конкретного Live Photo.

## Что ещё требует живой приёмки

Фактическая отправка новой версии через Telegram, групповые режимы и кнопки,
Business с обеих сторон, Instagram Story и карусель, остальные заявленные платформы,
перезапуск production и истечение реальных 72 часов. Автотесты не подменяют эти пункты.

После первого деплоя Telegram подтвердил отправку MP4, оригинальных фото и аудио
в личке. Пользователь подтвердил получение слайдшоу; Live Photo в нём остаётся
неподвижным из-за отсутствующей в веб-данных видеочасти. Это открытое ограничение.

Деплой выполняется существующим workflow: feature branch → PR checks → merge
→ полный CI → неизменяемый образ → резервная копия базы → healthy и HTTPS checks.
