# Сообщения об уязвимостях

В текущем приватном репозитории создай Issue с описанием проблемы и тестовым
примером: его видят пользователи с доступом к репозиторию. Не прикладывай рабочие
токены, cookies, содержимое переписок или дампы баз. Если репозиторий станет
публичным, для деталей уязвимости используй **Security → Report a vulnerability**,
если эта функция включена; в публичном Issue оставляй только общее описание.

В отчёте укажи коммит, конфигурацию без секретов, шаги воспроизведения и
затронутые данные. Используй тестовые аккаунты и собственные данные.

Отдельных веток с исправлениями для старых версий сейчас нет. Исправления
попадают в `main`; перед обновлением сохраняй резервную копию базы и медиа.

Проверки доступа к архиву, изоляции владельцев и сетевых ограничений находятся
в `tests/`. Их прохождение не заменяет аудит конфигурации сервера.
